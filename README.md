## 주요 기능
- 감정 입력 (일기 / 사진 / 음성 / 영상)
- 옵션(장르·악기·길이) 선택 → 길이를 반영한 가사 생성 (Gemini API)
- 완성된 노래 2곡(Ver.1, Ver.2)을 생성해서 마음에 드는 쪽 선택 (ACE-Step)
- 앨범 커버: 기본 그라데이션 커버 + 버튼으로 AI 커버 생성 (SDXL-Turbo, 스타일 5종)
- 앨범 커버 위에 가사 오버레이

## 기술 스택
| 구분 | 사용 |
|---|---|
| 프론트엔드 | Next.js |
| 백엔드 | FastAPI, Python |
| AI | Gemini API (가사), ACE-Step 1.5 (음악, 로컬 GPU), SDXL-Turbo (커버, 로컬 GPU) |
| 기타 | Pillow (기본 커버) |

## 구조
```
노래 생성:  /generate-music (Ver.1) → ACE-Step + 기본 커버
            /generate-music (Ver.2) → ACE-Step, 커버는 Ver.1 것 재사용
AI 커버:    /generate-cover-sdxl → 별도 프로세스에서 SDXL 실행 → 끝나면 프로세스 종료
            (실패하면 기본 커버로 자동 대체)
```

## 문제 해결 기록 (백엔드)
| 문제 | 원인 | 해결 |
|---|---|---|
| 노래+커버 같이 생성하면 두 번째부터 타임아웃 | `empty_cache()`로는 GPU가 반환되지 않음 (CUDA 컨텍스트는 프로세스가 살아있는 한 유지) + 좀비 프로세스 | SDXL을 별도 프로세스로 분리, 끝나면 종료해 GPU 100% 반환 |
| 미리듣기와 풀버전 멜로디가 다름 | 같은 seed라도 길이가 다르면 새로 생성됨 | 처음부터 풀버전 2곡 생성 방식으로 변경 |
| 인트로가 30초씩 늘어짐 | 가사 생성 때 노래 길이 정보가 없었음 | 옵션 선택 → 가사 생성 순서로 화면 재배치 |
| 성공 판정이 가끔 조용히 깨짐 | stdout 문자열 파싱이 버퍼링에 취약 | 결과 파일이 실제로 생겼는지로 판정 |

## 시도했지만 제외한 것
- 가사 싱크 자동 맞추기: 보컬 분리(Demucs) + VAD → 음량·지속시간 방식까지 시도했으나 곡마다 안정적이지 않아 최종 제외

## 배운 점
- 무거운 GPU 작업은 필요할 때만 별도 프로세스로 실행하고 끝나면 종료
- 결과 판정은 "결과물이 실제로 생겼는지"로
